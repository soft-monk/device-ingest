## 1. 三分钟跑通

```bat
:: 1) 独立构建（不需要主仓、不需要 vcpkg；nlohmann/json 已内置单头副本）
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release

:: 2) 起最小宿主（三个接入点在 45500/45501/45502 上收包）
build\bin\Release\host_demo.exe --verbose

:: 3) 另开一个窗口，发一包（这就是 S1 的验收）
build\bin\Release\device_sim.exe --port 45500 --kind uav.pos --devices 3 --hz 2 --seconds 5
```

第 2 步的窗口里应出现：

```
[log/acc] {"event":"started","points":3,"mergeWindowMs":100,...}
[telemetry.uav.pos] {"alt":1009.0,"battery":94,"deviceId":"sim-dev-1",...,"tsSource":"device",...}
[log/fan] {"batch":3,"merged":3,"windowMs":100}
```

**一条命令跑完 S1–S3 全部验收**（含零依赖自测）：

```bat
powershell -ExecutionPolicy Bypass -File scripts\acceptance.ps1
```

## 2. 构建选项

| 选项 | 默认 | 作用 |
|---|---|---|
| `DEVICE_INGEST_WITH_HUB` | `OFF` | 开 `ON` 才编 WS 广播层，**需要 Drogon**；`OFF` 时模块是"纯采集模式"，不含任何 Web 框架，可编到采集机上 |
| `DEVICE_INGEST_BUILD_TOOLS` | `ON` | 编 `tools/device_sim`（设备模拟器） |
| `DEVICE_INGEST_BUILD_EXAMPLES` | `ON` | 编 `examples/host_demo`（最小宿主） |
| `DEVICE_INGEST_BUILD_TESTS` | `ON` | 编 `tests/selftest`（零依赖自测） |
| `DEVICE_INGEST_WARNINGS_AS_ERRORS` | `OFF` | 把编译告警当错误 |

产物统一落在 `build/bin/<Config>/`：`host_demo.exe`（Linux 上无后缀）、`device_sim.exe`、`selftest.exe`。

**依赖**：只需要 C++17 编译器、CMake ≥ 3.20、线程库。
`nlohmann/json` 优先用系统/包管理器提供的；找不到就用仓内 `third_party/nlohmann/json.hpp`（v3.11.3 单头副本）。
`DEVICE_INGEST_WITH_HUB=ON` 时额外需要 Drogon。

**Linux / GCC**：把生成器换成默认即可（`cmake -S . -B build -DCMAKE_BUILD_TYPE=Release`）。
`cmake --build build` 不带 `--config`。

## 3. 作为子目录引入（宿主怎么接）

模块支持三种引入方式，都是 `add_subdirectory` 语义（README §接入方式）：

```cmake
# ① FetchContent（推荐：版本化引入）
FetchContent_Declare(device_ingest
  GIT_REPOSITORY https://github.com/soft-monk/device-ingest.git
  GIT_TAG        v0.1.0)
FetchContent_MakeAvailable(device_ingest)
target_link_libraries(your_app PRIVATE device_ingest)

# ② git submodule / ③ 本地 SOURCE_DIR：同样是 add_subdirectory(device-ingest)
```

宿主只需实现两个（可留空的）反向接口，模块即可工作：

```cpp
class MySink : public device_ingest::ISink {
    void onEvent(const device_ingest::IngestEvent& ev) override { /* 单条事件 */ }
    void onBatch(const std::vector<device_ingest::IngestEvent>& evs) override { /* 一批事件 */ }
    void onDeviceHealth(const device_ingest::DeviceHealthEvent& ev) override { /* 上线/离线/统计 */ }
    // onCommandState / onAlert 可选
};
class MyLog : public device_ingest::ILogSink { /* log / commandAudit，模块自己不落库 */ };

device_ingest::IngestConfig cfg;          // 可来自 config.json（契约 §3 结构）
cfg.points = { /* 接入点 */ };
device_ingest::Gateway::instance().start(cfg, std::make_shared<MySink>(),
                                        std::make_shared<MyLog>(), nullptr);
```

⚠️ **`onEvent` 与 `onBatch` 不会同时被调用**：配了合并窗（默认 100 ms）时只调 `onBatch`，
配 `mergeWindowMs = 0` 时只调 `onEvent`。只想处理单条就重写 `onEvent`（默认 `onBatch` 会转调过去）。

配置怎么给：`config::loadFile("config.json", cfg, err)` 或 `config::fromJsonString(text, cfg, err)`，
再 `config::applyEnvOverrides(cfg)` 让既有 `MAPAPP_UDP_*` 环境变量继续生效（契约 §3 降级约定）。

## 4. 工具怎么用

### `device_sim` · 设备模拟器（ING-NFR-06）

| 参数 | 说明 |
|---|---|
| `--host/--group <addr>` | 目标地址，默认 `127.0.0.1`（组播填 `239.x.x.x`） |
| `--port <n>` | 目标端口（= 接入点配置的 `port`） |
| `--kind <kind>` | `uav.pos` / `link.quality` / `target.state` / `node.state` / `raw` |
| `--devices/--hz/--seconds` | 台数 / 每台频率 / 运行秒数 |
| `--size <n>` | 报文目标字节数（默认 200，补 `padding` 字段） |
| `--drop-rate <pct>` | 丢包注入：**seq 照常递增但不发**，接收侧据此精确算丢包率 |
| `--shuffle-rate <pct>` | 乱序注入：按概率把 seq 写小 |
| `--stop-at <sec>` / `--restart-at <sec>` | 停机造离线 / 恢复造上线（seq 归零 = 设备重启语义） |
| `--id-prefix <s>` | 设备 id 前缀，便于在同一次验收里区分多个场景 |

复现验收场景（对应契约 §10 场景表）：

```bat
:: 丢包率精确统计：期望 packetLossRate ≈ 0.10
device_sim --port 45500 --devices 1 --hz 50 --drop-rate 10 --seconds 8

:: 乱序精确统计
device_sim --port 45500 --devices 1 --hz 50 --shuffle-rate 20 --seconds 4

:: 离线判定：3 s 内应出现 device.offline
device_sim --port 45500 --devices 1 --hz 1 --stop-at 2 --seconds 6

:: 协议未定的设备（原始透传）
device_sim --port 45501 --kind raw --size 200 --devices 1 --hz 1 --seconds 5
```

> ⚠️ **验收口径提示**：健康统计按 60 s 窗口累积（契约 §4.2）。
> 同一轮里先跑 A 设备再跑 B 设备，B 的 seq 会把 A 的 `maxSeq` 顶高，A 的丢包率会被算低。
> 要测精确值，**一个场景单独起一轮 host_demo**（`scripts/acceptance.ps1` 就是这么做的）。

### `host_demo` · 最小宿主（目标 G2）

```bat
host_demo                                :: 内置演示配置，端口 45500/45501/45502
host_demo --config config.json           :: 读契约 §3 结构的配置
host_demo --port 45600 --seconds 20      :: 换基端口、跑 20 秒
host_demo --verbose                      :: 打印模块日志（[log/acc] 等）
host_demo --report out.json              :: 退出时写机器可读报告（给验收脚本读）
```

`--report` 报告里含：接入点清单与指标、设备台账（含 `stats`：`packetLossRate` /
`outOfOrderCount` / `seqPrecise`）、总览、`sinkEvents`、`hubBroadcasts`。

### `tests/selftest` · 零依赖自测

```bat
selftest            :: 跑全部用例（约 20 s，含 3 s 离线判定等待）
selftest --list     :: 只列用例名
```

覆盖 S2/S3 的验收条目，**不需要外设、不需要网络**（全部走 `Gateway::inject` 在进程内驱动）。
配合 `ctest` 也可：`ctest -C Release --output-on-failure`。

## 5. 排障顺序（按命中率）

| 现象 | 先查 |
|---|---|
| `host_demo` 起不来 | 端口被占用（默认 45500/45501/45502）。换 `--port 45600`；`[log/acc]` 里有可读原因 |
| 接入点 `running:true` 但收不到包 | ① `device_sim --host` 与接入点 `group` 是否一致；② 组播时是否需显式 `iface`；③ 防火墙是否放行 UDP |
| `running:false` | 看 `[log/acc]` 的 `lastError`：`bind 失败`（端口被占）/ `join 组播失败`（多网卡需配 `iface`） |
| 有包但没事件 | `parseFailed` 是否在涨：报文不符合该解析器的约定，或 `parserId` 配错 |
| 事件数变成 2 倍 | 检查宿主是不是 `onEvent` 与 `onBatch` 都当"收到一条"处理了（二者不会同时调用，见 §3） |
| 丢包率恒为 0 但明显在丢 | 设备是否真带 `seq`；`seqPrecise` 是否为 `true` |
| 丢包率比预期低 | 统计窗（60 s）里是否混了别的场景/设备（见 §4 的口径提示） |
| 设备一直"离线" | `deviceId` 是否稳定（设备侧 id 变化会被当成新设备）；超时倍数是否过小 |
| 中文源码编译报奇怪错（MSVC） | 见 §6 |

## 6. 本仓踩过的两个编码坑（重要，改代码前先看）

### ① `src/util/time.h` 与 CRT 的 `<time.h>` 同名 → 改名 `clock.h`

`<ctime>` 内部会 `#include <time.h>`。只要 `src/util` 进入 include 路径，
命中的就是我们的 `time.h`（而不是 CRT 的），`<chrono>` / `<filesystem>` 整条链被打断，
MSVC 报一堆莫名其妙的错：

```
error C2653: “chrono”: 不是类或命名空间名称      ← 报在 MSVC 自己的 <chrono> 里
```

**因此**：该文件已改名 `src/util/clock.h`，且 `src/util` **不再加入 include 路径**，
src 内部一律用全路径 `#include "util/clock.h"`。加新的 util 头文件时请沿用这个规矩
（别把 `src/util` 塞进 `target_include_directories`）。

### ② 脚本与源码一律 UTF-8；`.ps1` 需要 BOM

- 源码（`.h/.cc`）写中文注释是允许的，但 **MSVC 必须加 `/utf-8`**（CMakeLists 已加）。
  不加会按系统代码页（本机 CP936）解码，UTF-8 中文会把后面的引号/换行吃掉，
  报出与代码无关的语法错。
- PowerShell **5.1** 对不带 BOM 的 `.ps1` 按 ANSI 解码 → 中文注释会把脚本读崩
  （报 `Missing closing ')'`、`Unexpected token` 之类）。
  所以 `scripts/acceptance.ps1` **带 UTF-8 BOM**；用编辑器改过之后请确认 BOM 仍在。
  用 PowerShell 7（`pwsh`）则默认 UTF-8，不受影响。
- 读 JSON 报告请用 `[System.IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)`，
  不要用 `Get-Content -Raw`（5.1 上按 ANSI 解码）。
