## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 新仓可**独立构建**（不依赖主仓任何头文件） | 空环境 `cmake -S . -B build && cmake --build build` 通过，产出库 + 两个工具 |
| G2 | 新仓可**独立运行**一个最小宿主（`examples/host_demo`），不连主仓数据库 | 运行后能用工具发 UDP，看到事件被打印/广播 |
| G3 | 主仓改为**消费者**：引入模块、实现两个反向接口（`ISink` / `IDeviceSource`），删除自有 UDP 接收代码 | 主仓 `build_all.bat` 通过；浏览器收到的 4 类既有事件与改造前逐字段一致 |
| G4 | 对外接口只经**两个反向接口 + 一个配置结构**，模块内部不出现任何主仓类型 | include 检查：模块源码中不出现业务类型、不出现 SQL 语句 |
| G5 | 可发布为子仓并与主仓双向同步 | `scripts/publish-device-ingest.bat`（subtree split）可重复执行 |

## 2. 现状耦合分析（拆仓要处理的全部障碍）

`net/Telemetry.cc` 只有 281 行，但缠了四根线 + 一根隐线。下表逐条给出**位置与处理方式**：

| # | 耦合 | 位置（现状） | 性质 | 处理 |
|---|---|---|---|---|
| ① | `EventHub::instance().broadcast(type, data)` | `Telemetry.cc:162 / 164 / 166 / 168 / 237 / 264 / 282 / 306` | **可带走**：广播出口本身属模块能力（含 WS 连接管理），不是业务 | `EventHub` 随模块走，主仓改为 `include <device_ingest/hub.h>` |
| ② | `Repo::nowMs()` | `Telemetry.cc:44` | 工具函数（一行） | 模块内自带 `util/time.h`；主仓不再提供 |
| ③ | `Config::instance().simEnabled / simIntervalMs` | `Telemetry.cc:69 / 175` | 配置读取 | 换成模块自有 `IngestConfig`（纯结构体，主仓组装后传入） |
| ④ | **业务表直查**：`SELECT id,scenario_key FROM mission`、`FROM grp`、`FROM link`、`FROM uav_resource`、`UPDATE mission SET progress` | `Telemetry.cc:189-197 / 242 / 245 / 271 / 280 / 290 / 293` | ⚠️ **最脏**：模拟器直接读写主仓业务 schema | 由 `IDeviceSource` 反向接口替代（§4） |
| ⑤ | **隐线**：`EventHub::logEvent()` 内部写库 | `EventHub.cc:68-70`（`Database::instance().raw()`） | 广播与 DB 通过 `logEvent` 缝合在一起 | `EventHub` 只保留广播；日志改为注入的 `ILogSink`（§3.2） |

**关键结论**：真正"干净可搬"的是 `udpLoop`（`Telemetry.cc:83-145`，接收循环）；脏的全在同一个文件里的 `simLoop`（`173-314`）——它既是模拟器又是业务数据生产者，这块必须切开。

**另需注意**：`Telemetry.h` 的 `injectPacket(const std::string& json)`（第 25 行）是"单包入口"，被模拟器与（潜在）测试复用。抽仓后保留为公开的**测试注入点**（`Gateway::inject(ingestId, bytes, peer)`），解析器与归一化逻辑因此可以脱离网络被单测。

### 3.1 分层与依赖方向（硬约束）

```
gateway（门面）
   ├─ acc ──▶ prs ──▶ nrm ──▶ fan ──▶ hub        数据面（单向）
   ├─ hlt ◀── acc/nrm（喂数据）  ──▶ hub          健康面（只读消费 + 事件）
   └─ cmd ──▶ acc（发 UDP）+ hlt（取设备地址）      控制面
hub ──▶ ISink（宿主实现，可空）                    出口反转
所有层 ──▶ util                                    无反向依赖
```

**禁止**：`acc/prs/nrm/fan` 不得 `#include` 任何 `hlt/cmd/gateway` 头文件（避免环）；模块内**不得出现 SQL**、不得 include `sqlite3.h`。

### 3.2 反向接口（宿主实现侧）

```cpp
// include/device_ingest/sink.h
namespace device_ingest {

// 数据出口：模块把归一化事件交给宿主（宿主一般转 WS 广播 / 落库 / 喂地图）
class ISink {
public:
    virtual ~ISink() = default;
    virtual void onEvent(const NormalizedEvent& ev) = 0;               // 每个归一化事件
    virtual void onBatch(const std::vector<NormalizedEvent>& evs) = 0; // 单帧合并后
    virtual void onDeviceHealth(const DeviceHealthEvent& ev) = 0;      // 上线/离线/丢包超阈值
    virtual void onCommandState(const CommandStateEvent& ev) = 0;      // pending/sent/acked/failed/timeout
    virtual void onAlert(const AlertEvent& ev) = 0;                    // 接入点故障、无主回执等
};

// 日志出口：替代我们现在直接写 event_log 表的那条线（现状 EventHub.cc:68-70）
class ILogSink {
public:
    virtual ~ILogSink() = default;
    virtual void log(const std::string& category, const nlohmann::json& payload) = 0;
    virtual void commandAudit(const CommandRecord& rec) = 0;           // ING-CMD-06 操作日志
};

}  // namespace device_ingest
```

- 两个接口**可由宿主留空**（模块仍能收包、仍会广播——因为 `hub` 自带 `EventHub`；`ISink` 主要给"不想用 EventHub 而想自己分发"的宿主）。
- 主仓的实现落点：`backend/src/ingest_bridge/`（新增小目录，保持主仓业务逻辑不污染模块）。

## 4. `IDeviceSource`：解决"模拟器要业务数据"的正面设计

**问题**：现状模拟器直接查 `mission / grp / link / uav_resource` 四张业务表（`Telemetry.cc:189-293`）。
**若把模拟器搬进模块而保留查表**，模块就永远拆不干净（带着主仓 schema）。

**做法**：把"业务 → 合成数据所需的最小事实"抽象成一个反向接口，**主仓实现它，模块只消费中立结构**。

```cpp
// include/device_ingest/device_source.h
namespace device_ingest {

// 中立结构：只描述"模拟要摆几台设备、摆在哪个区域、属于哪个编组"
struct SimMission { std::string id; std::string scenarioKey; double centerLng; double centerLat; };
struct SimGroup   { std::string id; std::string name; int seq; };

// 宿主实现：把业务表翻译成上面两个中立结构（主仓里就是三条 SELECT）
class IDeviceSource {
public:
    virtual ~IDeviceSource() = default;
    virtual std::vector<SimMission> missions() = 0;
    virtual std::vector<SimGroup>   groups(const std::string& missionId) = 0;
    // 设备"上报"是否也要落主仓业务表（现状 Telemetry.cc:280 直接 UPDATE mission.progress）
    //   返回 false = 模块不回调进度，进度推进由主仓自己的业务逻辑负责
    virtual bool acceptProgress() { return false; }
};

}  // namespace device_ingest
```

**四类现状查表 → 新归属（逐条对应）**

| 现状位置 | 查的表 | 新归属 | 保留方 |
|---|---|---|---|
| `Telemetry.cc:189-210` 建 6 架无人机（按 mission + grp） | `mission`, `grp` | `IDeviceSource::missions()/groups()` | **主仓实现**，模块调用 |
| `Telemetry.cc:242-267` 推链路质量 | `mission`, `link` | 同上（`SimMission` 增加可选 `links` 字段）或**留给主仓自己推** | 建议**留给主仓**：链路质量是业务语义，不该由外设模拟器造 |
| `Telemetry.cc:271-286` 推进任务进度 | `mission`（UPDATE） | `ISink` 或主仓自己的模拟器 | **必须留主仓**（写业务表是业务行为） |
| `Telemetry.cc:290-311` 推资源快照 | `uav_resource` | 同上 | **留主仓** |

> 边界很清楚：**模块只管"把设备报文收进来、解析、归一、发出去"；"演示数据长什么样、任务进度怎么走"是主仓的业务模拟**。这也顺带修掉了现状里"外设接收层擅自 UPDATE 业务表"这个隐患。

## 5. 配置结构与主仓组装

```cpp
// include/device_ingest/config.h
struct PointConfig {
    std::string id, group, iface, parserId, deviceType, topic;
    int port = 0;
    bool enabled = true;
    int timeoutMultiple = 3;           // 0 = 用全局
};
struct IngestConfig {
    bool enabled = true;
    int  mergeWindowMs = 100;          // ING-FAN-02；0 = 逐包直发
    int  defaultTimeoutMultiple = 3;   // ING-HLT-01
    int  healthWindowSec = 60;         // ING-HLT-03
    int  cmdTimeoutMs = 1000;          // ING-CMD-04
    int  cmdMaxRetries = 2;
    size_t queueLimit = 20000;         // ING-NFR-05
    size_t ledgerLimit = 20000;
    size_t commandLogLimit = 10000;
    std::vector<PointConfig> points;   // 空 = 回落单接入点（契约 §3）
};
```

**主仓组装点**（改造后）：`backend/src/core/Config.cc` 读 `config.json` 的 `ingest` 段 → 填 `IngestConfig` → `main.cc` 调 `Gateway::instance().start(cfg, sink, logSink, deviceSource)`。
**兼容**：未配置 `ingest` 段时，主仓用既有 `MAPAPP_UDP_GROUP / MAPAPP_UDP_PORT / MAPAPP_UDP_ENABLED` 组装**单个**接入点，行为与改造前一致（契约 §3 降级约定）。


## 8. 构建与集成

### 8.1 新仓独立构建

```cmake
# device-ingest/CMakeLists.txt（要点）
cmake_minimum_required(VERSION 3.20)
project(device_ingest CXX)
set(CMAKE_CXX_STANDARD 17)                 # 与主仓一致
option(DEVICE_INGEST_WITH_HUB "编译 EventHub（需要 drogon）" ON)
option(DEVICE_INGEST_BUILD_TOOLS "编译模拟器与回声端" ON)

find_package(nlohmann_json CONFIG REQUIRED)
if(DEVICE_INGEST_WITH_HUB)
  find_package(Drogon CONFIG REQUIRED)     # 仅 hub/ 需要；采集机无 WS 时可 OFF
endif()

add_library(device_ingest STATIC src/...)  # 或 SHARED
target_include_directories(device_ingest PUBLIC include)
```

- `DEVICE_INGEST_WITH_HUB=OFF` 时，模块退化为"纯接入 + 队列 + 回调"，可编译到**没有任何 Web 框架**的采集机上（这也是"独立部署"的底气）。
- **不依赖 sqlite3**：日志与业务落库全部经 `ILogSink` 由宿主实现。
