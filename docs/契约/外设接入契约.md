# 外设接入契约（v1.0）

> 本文件是**外设接入层对外接口的唯一基准**：接入点配置、归一化对象、事件名、REST 与指令报文，全部以本文件为准。
> 需求依据：[../02-技术需求/外设接入需求专篇.md](../需求/外设接入需求专篇.md)（编号 `ING-<域>-<序号>`）。
> 与主契约的关系见 §0；**本批不修改**《开发接口契约规格书》，待稳定后再并入其 §4 / §9。

---

## 0. 范围与与其他契约的关系

- 本契约覆盖：**外设接入层**（后端 C++ 模块）的配置结构、归一化数据形状、事件名、REST 接口、UDP 指令与回执、错误码。
- **不覆盖**：地图渲染契约（见 `map-2d/doc/接口文档.md`）、业务 REST 主体（见《开发接口契约规格书》§3）、AI 桥。
- 冲突处理顺序：本文件 → 《开发接口契约规格书》（**端口、时间、响应体信封、WS 信封**仍以主契约为准）→ 《技术需求文档》。
- 兼容承诺：§4 的**既有 4 个事件名与字段**属兼容范围，新增字段只增不改；破坏性变更需经过至少一个次版本的废弃过渡期。

## 1. 统一约定

| 项 | 取值 |
|---|---|
| REST 前缀 | `/api/v1/ingest` |
| 响应体 | `{ "code": 0, "message": "ok", "data": { } }`；`code=0` 成功，非 0 见 §8 |
| HTTP 状态码 | 仍语义化（200/400/404/409/500），业务错误以 `code` 为准 |
| WS 信封 | `{ "type": "...", "data": { ... }, "ts": <epoch 毫秒> }` |
| 时间戳 | epoch 毫秒（整数）；人类可读时间为本地串 `YYYY-MM-DD HH:mm:ss` |
| ID 形态 | `ingestId` / `deviceId` / `cmdId` 均为字符串；`cmdId` 由服务端生成，全局唯一 |
| 坐标 | WGS84，顺序 `[经度, 纬度]`（GeoJSON 惯例）；高度米；速度 m/s；航向 0–360 度 |
| 幂等 | 写操作幂等：重复下发同一 `cmdId` 返回首次结果并标 `code=1001` |
| 端口规划 | **一个 UDP 端口只归一个接入点**（见需求专篇 R6）；新增端口 MUST 避开 `8080`（HTTP/WS）与 `8090`（AI 桥） |

## 2. 归一化对象（接入层对外唯一数据形状）

> 对应 `ING-NRM-01`。所有解析器的输出、所有事件与接口的数据，都是这个形状或其数组。

```jsonc
{
  "deviceId":   "uav-001",          // MUST，字符串，接入层内稳定唯一
  "deviceType": "uav",              // MUST，设备类型（uav/radar/electronic/comm/...）
  "kind":       "uav.pos",          // MUST，事件种类（见 §5 事件名表）
  "lng": 116.3974,                  // 坐标：WGS84 经度；非法/越界则整字段缺失
  "lat": 39.9093,                   // 坐标：WGS84 纬度
  "alt": 900.0,                     // 可选，米
  "heading": 128.5,                 // 可选，0–360 度
  "speed": 22.4,                    // 可选，m/s
  "battery": 85,                     // 可选，0–100 整数
  "seq": 10241,                     // 可选，设备序号（有则丢包/乱序精确统计）
  "ts": 1789000000123,              // MUST，时间戳（epoch 毫秒）
  "tsSource": "device",             // MUST，"device" = 用报文内 ts；"server" = 用到达时刻补
  "recvAt": 1789000000140,          // MUST，服务端到达时刻（epoch 毫秒）
  "quality": { "signal": -67 },     // 可选，质量附加字段（按设备类型自定义）
  "source": {                       // MUST，溯源信息
    "ingestId": "ingest-uav-a",     // 接入点 id
    "peer": "192.168.1.31:51000",   // 来源地址:端口
    "bytes": 200                    // 原始包长度
  },
  "raw": "aa01..."                  // 可选，仅 raw 透传或显式开启溯源时出现（十六进制摘要）
}
```

**降级约定（MUST）**

| 情况 | 行为 |
|---|---|
| 坐标缺失 / 非数字 / 越界 | 丢弃 `lng`、`lat` 字段，事件仍上行；越界计数 +1 |
| `ts` 缺失或非数字 | 用服务端 `recvAt` 填充 `ts`，并置 `tsSource: "server"` |
| `seq` 缺失 | 不填 `seq`；该设备的丢包/乱序标记为"不可精确统计"（`ING-HLT-04`） |
| `deviceId` 缺失 | 用 `source.peer` 作为兜底 `deviceId`，并计数告警 |
| 未知字段 | 原样忽略，不进归一对象（不报错） |

## 3. 接入点配置

> 对应 `ING-ACC-01/02/03`。全部来自配置（`backend/config.json` 的 `ingest.points[]` 或环境变量），无硬编码。

```jsonc
{
  "ingest": {
    "enabled": true,
    "mergeWindowMs": 100,            // 单帧合并窗口；0 = 逐包直发（ING-FAN-02）
    "defaultTimeoutMultiple": 3,     // 失联倍数默认值（ING-HLT-01）
    "points": [
      {
        "id": "ingest-uav-a",        // MUST 唯一
        "enabled": true,
        "group": "239.10.10.10",     // 组播地址；空 = 收单播
        "port": 45454,               // MUST，一个端口只归一个接入点
        "iface": "",                 // 可选，绑定网卡地址（多网卡环境建议显式指定）
        "parserId": "uav.json.v1",   // MUST 已注册的解析器
        "deviceType": "uav",         // 该接入点的默认设备类型
        "topic": "telemetry.uav.pos",// 归一后事件名（见 §5）
        "timeoutMultiple": 3         // 可选，覆盖全局
      },
      {
        "id": "ingest-radar-a",
        "enabled": true,
        "group": "239.10.10.11",
        "port": 45455,
        "parserId": "radar.bin.v1",
        "deviceType": "radar",
        "topic": "telemetry.radar.detect"
      }
    ]
  }
}
```

**与环境变量的关系**：既有 `MAPAPP_UDP_GROUP` / `MAPAPP_UDP_PORT` / `MAPAPP_UDP_ENABLED` 继续有效；未配置 `ingest.points` 时，回落为**单个**接入点（group/port/enabled 取上述环境变量），解析器用既有 4 类 `kind` 分派实现（`ING-PRS-05`）。

**运行时变更**：`POST /api/v1/ingest/points` 热增，`DELETE /api/v1/ingest/points/{id}` 热删；两者 MUST NOT 影响其它接入点（`ING-NFR-03`）。

## 4. REST 接口

### 4.1 接入点

| 方法 | 路径 | 用途 | data |
|---|---|---|---|
| GET | `/api/v1/ingest/points` | 接入点清单 + 运行状态 | `[{ id, enabled, group, port, parserId, deviceType, topic, running, lastRecvAt }]` |
| POST | `/api/v1/ingest/points` | 新增接入点（热生效） | 新接入点对象（含 `running`） |
| DELETE | `/api/v1/ingest/points/{id}` | 移除接入点 | `{ id, removed: true }` |
| GET | `/api/v1/ingest/points/{id}/metrics` | 接入点级指标（`ING-ACC-06`） | `{ id, packets, bytes, dropped, parseFailed, lastRecvAt, dropReasons: {...} }` |
| GET | `/api/v1/ingest/parsers` | 已注册解析器清单 | `[{ parserId, name, version, deviceType }]` |

### 4.2 设备台账与健康

| 方法 | 路径 | 用途 | data |
|---|---|---|---|
| GET | `/api/v1/ingest/devices` | 设备台账（`ING-HLT-05`） | `[{ deviceId, deviceType, firstSeen, lastSeen, online, offlineSec, lastPos:{lng,lat,alt}, seq, stats:{...} }]` |
| GET | `/api/v1/ingest/devices/{id}` | 单设备详情 | 台账单条 + `stats` |
| GET | `/api/v1/ingest/devices/{id}/health` | 健康与统计（`ING-HLT-03/04`） | `{ deviceId, online, packetLossRate, outOfOrderCount, outOfOrderRate, seqPrecise: true\|false, windowSec, timeoutSec, reason? }` |
| GET | `/api/v1/ingest/health` | 接入层总览（可并入 `/api/v1/health` 的 `link` 模块项） | `{ points: n, devices: n, online: n, packetsPerSec, dropTotal }` |

**`seqPrecise` 语义（MUST 区分）**：`true` = 设备带 `seq`，`packetLossRate` / `outOfOrderRate` 为**精确值**；`false` = 无 `seq`，此时 `packetLossRate` 与 `outOfOrderRate` MUST 返回 `null`，并在 `reason` 写明"设备报文无 seq，不可精确统计"——**禁止返回估计值冒充精确值**。

**丢包率口径**（`ING-HLT-03`）：窗口内 `(maxSeq - minSeq + 1 - 实收数) / (maxSeq - minSeq + 1)`；窗口默认 60 s，可配置。乱序口径（`ING-HLT-04`）：后到包 `seq` < 窗口内已见最大 `seq`，计一次乱序。窗口内 `seq` 回绕（设备重启导致 `seq` 重置）时 MUST 视为**新会话**，不计为负丢包。

### 4.3 指令

| 方法 | 路径 | 用途 | 请求 / data |
|---|---|---|---|
| POST | `/api/v1/ingest/commands` | 下发指令（`ING-CMD-01`） | 请求见下；data `{ cmdId, state:"pending", target, sentAt }` |
| GET | `/api/v1/ingest/commands/{cmdId}` | 指令状态与时间线（`ING-CMD-05`） | `{ cmdId, state, target, type, payload, timeline:[{at,event,detail}], retries, ack? }` |
| GET | `/api/v1/ingest/commands?deviceId=&from=&to=&state=` | 指令列表 | `[{ cmdId, state, type, target, sentAt, ackedAt }]` |
| POST | `/api/v1/ingest/commands/{cmdId}/retry` | 手工重传一次 | `{ cmdId, state, retries }` |
| GET | `/api/v1/ingest/logs?deviceId=&from=&to=&limit=` | 操作日志（`ING-CMD-06`） | `[{ at, actor, cmdId, deviceId, action, payloadDigest, result }]` |

**下发请求体**

```jsonc
{
  "target": { "deviceId": "uav-001" },        // 二选一：单播到设备（用其最近来源地址或台账地址）
  // "target": { "ingestId": "ingest-uav-a" },// 或组播到某接入点
  "type": "uav.goto",                          // 指令类型（设备指令集定义，待确认项）
  "payload": { "lng": 116.40, "lat": 39.91, "alt": 900 },
  "timeoutMs": 1000,                           // 可选，默认 1000
  "maxRetries": 2,                             // 可选，默认 2
  "actor": "operator-01"                       // 谁发的（写入操作日志）
}
```

**指令状态机（MUST）**

```
pending ──发送──▶ sent ──收到匹配回执──▶ acked
                   │
                   ├──重传 N 次仍无回执──▶ timeout
                   └──发送失败/设备拒绝──▶ failed
```

- 每次重传 MUST 追加一条 `timeline` 记录，`retries` 递增；
- `timeout` 与 `failed` MUST 区分（对应风险 R5：单向 UDP 下"已执行但回执丢失"只能表现为 `timeout`，MUST NOT 与 `failed` 混为一谈）。

## 5. 事件名（WS 上行）

> 信封沿用主契约 §4：`{ type, data, ts }`。**既有 4 个事件名与字段是兼容范围**（`ING-PRS-05`）。

| type | 状态 | data 关键字段 | 来源 |
|---|---|---|---|
| `telemetry.uav.pos` | **既有，字段只增不改** | `{ uavId, groupId, type, lng, lat, alt, heading, speed, battery, ts }` + 新增可选 `{ deviceId, seq, tsSource, source }` | 契约 §4 / `ING-PRS-05` |
| `telemetry.link.quality` | **既有** | `{ linkId, from, to, signal, bandwidthMbps, latencyMs, lossRate, coverageKm2, meshProgress, state }` | 契约 §4 |
| `target.state` | **既有** | `{ targetId, targetNo, threat, confidence, dynamicState, lng, lat, status }` | 契约 §4 |
| `node.state` | **既有，语义扩展** | `{ nodeId, name, online, lastSeen }` + 新增可选 `{ deviceType, offlineSec, reason:"timeout" }` | 契约 §4 / `ING-HLT-06` |
| `device.online` | 新增 | `{ deviceId, deviceType, online:true, offlineSec }` | `ING-HLT-02` |
| `device.offline` | 新增 | `{ deviceId, deviceType, online:false, lastSeen, timeoutSec, reason:"timeout" }` | `ING-HLT-01` |
| `device.stats` | 新增（低频，默认 5 s 一次） | `{ deviceId, packetLossRate, outOfOrderRate, seqPrecise, windowSec }` | `ING-HLT-03/04` |
| `command.state` | 新增 | `{ cmdId, deviceId, state:"sent"\|"acked"\|"failed"\|"timeout", retries, detail? }` | `ING-CMD-05` |
| `alert` | 既有，复用 | `{ level:"info"\|"warn"\|"critical", code, title, text }`（丢包超阈值、接入点故障用此） | 契约 §4 / `ING-ACC-04` |

**事件名与归一对象的关系**：`topic`（接入点配置）决定走哪个事件名；`kind` 与事件名一一对应（如 `kind:"uav.pos"` ↔ `type:"telemetry.uav.pos"`）。新增设备类型的 `topic` 由接入点配置声明，**不需要改前端才能收到**（未知 type 前端忽略即可）。

## 6. UDP 指令与回执报文（接入层 ↔ 设备）

> 对应 `ING-CMD-02/03`。设备指令集尚未定稿（需求专篇 §9 待确认 2），本节给出**接入层侧的封装约定**，设备侧字段可按实际协议替换，但 `cmdId` 回填与回执语义为 MUST。

**下发报文（JSON over UDP，UTF-8）**

```json
{ "cmdId": "c-7f3a91", "type": "uav.goto", "ts": 1789000000123,
  "payload": { "lng": 116.40, "lat": 39.91, "alt": 900 } }
```

**回执报文**

```json
{ "kind": "cmd.ack", "cmdId": "c-7f3a91", "deviceId": "uav-001",
  "ok": true, "detail": "accepted", "ts": 1789000000456 }
```

**约定**

| 项 | 约定 |
|---|---|
| `cmdId` | 服务端生成；设备回执 MUST 原样回填 |
| 回执超时 | 默认 1 s（`timeoutMs` 可覆盖） |
| 重传 | 默认 2 次（`maxRetries` 可覆盖），间隔 = `timeoutMs` |
| 无主回执 | 匹配不到在途指令的回执 MUST 计数并上报告警，MUST NOT 静默丢弃（`ING-CMD-03`） |
| 二进制协议 | 若设备指令为二进制，由**该设备的解析器插件**负责编解码，本节的 JSON 形态仅是默认实现 |

## 7. 解析器插件接口

> 对应 `ING-PRS-01/02/04`。伪代码（C++）：

```cpp
// 一个包 → 0..N 个事件；解析器 MUST 无状态、可重入
struct ParsedEvent {
    std::string deviceId;
    std::string kind;        // 与 topic 对应
    nlohmann::json fields;   // 业务字段（lng/lat/alt/...）
    long long ts = 0;        // 设备时间戳，0 = 缺失
    long long seq = -1;      // 设备序号，-1 = 缺失
    nlohmann::json quality;  // 可选
};

class IParser {
public:
    virtual ~IParser() = default;
    virtual std::string id() const = 0;          // 如 "uav.json.v1"
    virtual std::string deviceType() const = 0;  // 如 "uav"
    // 返回 false = 无法解析（计入 parseFailed，不抛异常也应如此）
    virtual bool parse(const char* data, size_t len,
                       const std::string& peer,
                       std::vector<ParsedEvent>& out) = 0;
};
```

**注册**

```cpp
ParserRegistry::instance().add(std::make_unique<UavJsonParser>());
ParserRegistry::instance().add(std::make_unique<RawPassthroughParser>());  // 内置，id = "raw.passthrough"
```

**隔离要求（MUST）**：`parse()` 抛异常时接入层捕获并计入 `parseFailed`，该接入点继续工作；接收线程 MUST NOT 因解析失败退出。

## 8. 错误码

| code | 含义 | 典型场景 |
|---|---|---|
| 0 | 成功 | — |
| 1001 | 已执行（幂等） | 重复下发同一 `cmdId` |
| 2001 | 参数非法 | 接入点缺 `port`/`parserId`；`timeoutMs` ≤ 0 |
| 2002 | 资源不存在 | `deviceId` / `cmdId` / `ingestId` 不存在 |
| 3001 | 解析器未注册 | 接入点引用了未注册的 `parserId` |
| 3002 | 端口不可用 | bind 失败 / 端口被占（错误信息含端口与原因） |
| 3003 | 组播加入失败 | join 失败（含地址与网卡提示） |
| 3004 | 解析失败 | 报文不符合该解析器约定（单包级，通常只计数不返回） |
| 4001 | 指令下发失败 | 目标设备无可用地址 / 发送通道不可用 |
| 4002 | 指令超时 | 重传耗尽仍无回执（同时把指令状态置 `timeout`） |
| 5001 | 接入层未启用 | `ingest.enabled = false` |

## 9. 降级矩阵

| 场景 | 行为 |
|---|---|
| 无任何 `ingest.points` 配置 | 回落既有单接入点（`MAPAPP_UDP_*`），行为与改造前一致 |
| 某接入点端口被占 | 该接入点标 `running:false` + 可读原因；其它接入点正常；`/api/v1/health` 的 `link` 项给降级说明 |
| 解析器未注册 | 拒绝该接入点启动（`code=3001`），不影响其它接入点 |
| 报文不符合协议 | 计入 `parseFailed`，丢弃该包，不产生事件 |
| 设备离线 | 发 `device.offline` + `node.state`；台账保留该设备并标离线；地图侧由宿主决定是否隐藏 |
| 设备无 `seq` | 健康接口 `seqPrecise:false`，丢包/乱序返回 `null` 与原因 |
| 指令无回执 | 重传 → `timeout`，操作日志完整记录；不自动重试到设备恢复（由操作员或业务侧重发） |
| 前端 WS 断开 | 接收与队列继续工作（不背压接收线程）；重连后按现状继续收新事件（**本轮无补偿回放**，见决策 D1） |
| 队列超上限 | 按最旧淘汰并计数告警（`ING-NFR-05`），不影响接收 |

## 11. 排障顺序（按命中率）

| 现象 | 先查 |
|---|---|
| 接入点 `running:true` 但收不到包 | 组播地址/端口是否与发送端一致；多网卡环境是否需显式 `iface`；防火墙是否放行 UDP |
| `running:false` | `GET /points` 看原因：`code=3002` 端口被占 / `3003` join 失败 / `3001` 解析器未注册 |
| 有包但无事件 | `parseFailed` 是否增长（报文不符合该解析器约定）；`parserId` 是否配错 |
| 事件到了但前端地图没动 | 属**地图侧**问题：查阶段规则（T0–T2 不显示目标/无人机）、图层分组开关、`mapCommands.getStats().primitives` |
| 设备一直"离线" | `deviceId` 是否稳定（设备侧 id 变化会被当成新设备）；超时倍数是否过小 |
| 丢包率恒为 0 但明显丢包 | 设备是否真的带 `seq`；`seqPrecise` 是否为 `true` |
| 指令一直 `sent` | 设备是否回执；UDP 目标地址是否为设备真实来源地址（NAT 环境下可能不同） |
